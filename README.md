# 🕯 暖归 · 宠物善终服务预约告别与骨灰寄存平台

围绕**同一只宠物**，让宠物主人、客服、接送员、礼仪师、火化师、纪念品制作、财务和管理者在同一工单上协同，
全流程记录承诺时间、见证材料、费用变化与家属确认，敏感争议可追溯到具体交接节点。

- 后端：NestJS 11 + TypeORM + MySQL/MariaDB（端口 4000）
- 前端：Next.js 14 (App Router) + React 18（端口 3000）
- 数据库：本地免安装 MariaDB 10.11，**无需 root / docker / apt**，脚本自动下载到 `.local/`
- 同时提供 Docker Compose 一键启动（见下文「方式 C」）

---

## 一、本地启动

### 方式 A：一键脚本（推荐）

```bash
bash scripts/setup.sh   # 首次：下载 MariaDB → 建库建表 → 装依赖 → 写入种子账号与资源
bash scripts/dev.sh     # 启动：MariaDB + 后端 4000 + 前端 3000
```

打开 http://127.0.0.1:3000

### 方式 B：手动分步

```bash
# 1. 数据库（当前用户运行，数据在 .local/mysqldata）
.local/mysqlctl.sh start      # 启动（首次自动初始化、建库 pet_aftercare、建号 petapp/petapp123）
.local/mysqlctl.sh status     # 查看状态
.local/mysqlctl.sh stop       # 停止

# 2. 后端
cd backend
npm install
npm run seed                  # 建表（synchronize）+ 写入种子数据
npm run dev                   # http://127.0.0.1:4000

# 3. 前端（新终端）
cd frontend
npm install
npm run dev                   # http://127.0.0.1:3000
```

数据库连接可用环境变量覆盖：`DB_HOST / DB_PORT / DB_USER / DB_PASS / DB_NAME`。
若要连接已有的 MySQL，把这几个变量指向你的实例后直接 `npm run seed` 即可。

### 方式 C：Docker Compose 一键启动（无需本机 Node/MariaDB）

```bash
docker compose up --build
```

- 前端：http://localhost:3000　后端：http://localhost:4000
- 首次启动时后端自动建表（`synchronize`）并写入种子账号与资源；数据持久化在 `mariadb-data` 卷，
  之后重启容器不会清空业务数据（仅在库为空时执行 seed）。重置演示数据：
  `docker compose down -v && docker compose up --build`。

> 重置演示数据：`cd backend && npm run seed`（清空并重建业务数据）

## 四、已实现的需求场景

1. **客服确认方案**：系统按体重档位与服务选项生成建议报价（支持自定义总价），生成家属「服务方案确认」。
2. **调度排期**：一次排定接送员、冷藏暂存位、火化炉档期、告别室档期；火化炉/告别室同时段冲突会被拦截；重调度自动释放旧档期；按选项自动生成纪念品制作单。
3. **临时更改仪式时间**：家属发起改期申请 → 客服同意后告别室档期自动重排；驳回也留痕。
4. **体重与报价不符**：接送员接运复称后，按 20 元/kg 自动生成多退少补的费用变更，**必须家属确认**；存在未确认变更时火化环节被系统拦截。
5. **接送交通延误**：接送员上报分钟数与原因，承诺接运时间自动顺延，并在工单留言中通知家属。
6. **视频见证**：家属随时登记视频见证，火化完成时校验见证安排，证明中记录。
7. **纪念品制作失败处理**：开始 / 失败（登记原因并**消耗一份剩余材料**）/ 完成。失败后平台**关联制作人、剩余可用材料（爪印泥/留存毛发份数）与主人选择**：
   - 客服可提供 **重做 / 退款 / 替代纪念品** 三种方案，必须填写**不可逆风险告知**（材料不可再生、二次制作仍可能失败）；
   - 方案先经 **制作主管复核**（校验材料余量、风险与费用），通过后向主人发出确认；被驳回客服可在原单修订重提；
   - **主人确认**后：重做占用 1 份剩余材料并更新制作排期（承诺 3 日交付）；替代纪念品新建制作单排入档期；退款/差价生成费用变更——**费用调整与制作排期同步更新**；
   - **费用变化同步财务**（站内消息 + 处理单，财务确认入账/执行退款）、**制作人员同步查看**重做排期；失败立即生成客服关怀回访；
   - 最终由**家属 1–5 星评价**闭环；失败方案未获主人确认会阻止工单完结。
8. **骨灰盒寄送破损**：登记快递单号 → 在途 → 家属反馈破损（照片+描述，触发关怀回访）→ 补发新单号 → 送达 → 家属确认完好签收。
9. **寄存到期未续费**：柜位 30 天内到期标记 `expiring` 并生成续费提醒；已过期标记 `expired` 并生成跟进；续费后自动关闭待办提醒。
10. **多门店 / 医院转介**：员工数据按门店隔离，管理者可看全部门店；主人下单可选转介医院。
11. **费用与财务**：基础报价与每次变更分行留痕，变更项需家属确认；财务登记收款/退款；完结前校验结清。
12. **见证材料与追溯**：每个交接节点（接运、入冷藏、告别、入炉、出炉、证明、寄送、入柜、回访…）都有操作人、角色、承诺时间、实际时间、备注、照片/视频 URL，时间线中异常（⚠）与已闭环（✓）一目了然。
13. **服务后留存**：交接照片、火化证明编号、寄存位置、寄送单号、费用明细、情感回访记录全部沉淀在工单详情。


`scripts/demo-flow.ts` 通过真实 HTTP API 走通全部场景：

**4.2kg→5.0kg 自动补差 16 元** → 家属确认补差 → 家属改期并被批准 → **视频见证** →
冷藏 → 告别 → 火化（含未确认费用拦截校验）→ 火化证明 →
纪念品失败处理三线并行：**爪印泥失败→重做（材料 2→1→0、主管复核、主人确认风险、3 日排期、5 星评价）**；
**毛发瓶失败→替代被拒→退款（主管复核、主人确认、财务退 180 元、4 星评价）**；
**相册失败→替代为琉璃挂饰（+50 元、新制作单排期、财务确认补收、5 星评价）** →
骨灰盒**寄送破损→补发→签收** → 财务收款 2026 元 → 完结（自动排 7 日安抚回访）→
第二只宠物（兔）跨店走通入柜寄存 → 柜位到期扫描。

### 本次开发实际验证结论

- `tsc --noEmit` 后端类型检查通过；`next build` 前端生产构建通过（12 个路由，含 `/memento-cases` 失败处理队列）。
- `npm run seed`：2 门店、**15 个账号**（新增制作主管 `sup1`、2 号店制作人 `art2`）、冷藏/火化炉/告别室/24 柜位写入成功。
- `npm run demo`（实际执行，末单 `completed`，时间线 53 个可追溯节点）覆盖纪念品失败处理三条路径并对账一致：
  - **爪印泥重做**：材料 2 份 → 失败耗 1 → 主人确认重做再占 1 → 0 份；`remake_count=1`，承诺 3 日交付，家属 5 星；
  - **毛发纪念瓶退款**：替代吊坠方案被主人拒绝 → 改提退款 180 元 → 主管复核 → 主人确认 → 财务退款 → 4 星；
  - **相册失败改替代**：琉璃画像挂饰 +50 元，新制作单自动排入档期，财务确认补收，5 星；
  - 费用对账：报价 2010 + 体重补差 16 − 退款 180 + 替代差价 50 = **应收 1896，已收 1896，余额 0**；
    管理者总览 `open_exceptions=0 / failed_mementos=0 / 待复核=0 / 待主人确认=0`。
- 规则拦截实测：缺不可逆风险告知 → 400；处理单复核/确认流程中重复提案 → 400；退款方案费用栏非负数 → 400；
  材料为 0 时提案重做 → 400；**客服替主人确认失败方案 → 403（须主人本人确认）**。
- 越权校验：2 号店客服/司机访问 1 号店工单返回 `403 跨门店数据不可访问`；主人访问他人工单返回 403；
  1 号店制作主管在处理队列中只见本店 3 条处理单（2 号店第二单不可见）。

前端页面的操作通过后端 API 闭环验证；图形界面建议按 `demo-flow` 的顺序在浏览器点验一遍：
`owner1` 下单 → `cs1` 核定+调度 → `driver1` 延误/接运 → `owner1` 确认费用/改期 →
`rite1` 告别 → `fire1` 火化 → `art1` 纪念品登记失败 → `cs1` 提出失败方案（重做/退款/替代+风险）→
`sup1` 制作主管复核 → `owner1` 确认方案/评价 → `fin1` 退款或确认补收 →
`cs1` 寄送破损补发 → `fin1` 收款 → `cs1` 完结 → `manager1` 看总览。

> 浏览器点验失败处理的最短路径：`art1` 对「爪印纪念品」点「登记失败」→ `cs1` 在工单右侧纪念品面板
> 「提出处理方案」（选重做、风险已预填）→ `sup1` 在 `/memento-cases` 或工单内「复核通过」→
> `owner1` 在顶部待确认卡片阅读不可逆风险后「同意确认」→ 工单内可看到材料份数扣减、重做 3 日排期，
> `art1` 完成重做 → `owner1` 点「评价处理结果」。
